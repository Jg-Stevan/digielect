# Worklog — Proyecto Digielect (Sistema de Digitalización Electoral E-14)

## Contexto General
- Repo origen clonado en `/home/z/digielect` (Vite + React, mock data, docs ERS, diseños HTML).
- Objetivo: migrar el sistema completo al proyecto Next.js 16 de `/home/z/my-project` (App Router, Tailwind 4, shadcn/ui, Prisma/SQLite).
- Diseño "Precision Monitor": dark mode, fondo #0E1414, verde #00C853, amarillo #FFD600, rojo #FF5252. Fuentes: Hanken Grotesk (estructura) + JetBrains Mono (números/tablas).
- Documentos clave del origen:
  - `/home/z/digielect/Proyecto en General/Especificación de Requerimientos de Software (ERS).md` (reglas de negocio RN-01..RN-06, RF, RNF)
  - `/home/z/digielect/Proyecto en General/El Flujo de Validación y Aprobación Operativa.md`
  - `/home/z/digielect/CONTEXTO INICIAL/Que datos contiene un Acta E-14.md` (estructura del acta y código de barras 15D)
  - Mock data: `/home/z/digielect/src/mockData.ts` + tipos en `/home/z/digielect/src/types.ts`
- Actas E-14 reales de ejemplo (PDF): `/home/z/digielect/PROYECTO ELECTORAL/prueba de claude/DOCUMENTACION/ACTAS DE EJEMPLO/` (4 PDFs, DIVIPOL 88/335/005 etc.)

## Decisiones de Arquitectura
- Una sola ruta visible: `/` (src/app/page.tsx). La app es un shell SPA con navegación interna entre vistas.
- Dos "aplicaciones" dentro del shell: Panel Supervisor (desktop) y PWA Digitalizador (vista emulada tipo móvil, accesible desde el shell).
- APIs REST bajo `/api/*` con Prisma (SQLite en `db/custom.db`).
- Análisis IA de actas con VLM (z-ai-web-dev-sdk) desde backend: score de calidad 0-10, detección de firmas, lectura de código de barras 15D y extracción de datos de votación (RN-02, RF-1.2).
- Estados de un acta (matriz ERS): PENDIENTE / VALIDADO / RECHAZADO / ANOMALIA / OFFLINE.
